# 30초 실기 촬영 · 현장 점검 시나리오

실제 웹캠 + 사람으로 하는 검증 절차입니다. 결과는 **초기 목표 대비 관찰값**으로 기록하고, 합격/불합격 사양으로 단정하지 마세요.
자동(합성) 테스트 결과와 **섞지 마세요**.

## 준비

- PC 1대 · 웹캠 1대 · 디스플레이 1대. `npm run dev` 또는 `npm run preview` 후 브라우저 전체화면.
- 운영자 패널에서 **카메라 시작** → ROI를 체험 구역에 맞추고 **시선 보정**(좌우 반전/게인) 완료.
- 기록 항목: 장비 모델, 조명 조건, 입력 해상도, 측정 방법, 렌더/인식 FPS, 지연 측정법.
- 화면 녹화(또는 삼각대 카메라로 화면+사람 동시 촬영)를 켭니다.

## 촬영 컷 (각 30초 내외)

1. **무인 30초** — 아무도 없을 때. 잘못된 환영/하이파이브가 **0회**인지. (오작동 카운트)
2. **입장 & 시선** — 한 명이 ROI에 들어와 좌우로 10회 이동. 캐릭터가 **방향을 반전**하며 따라보는지, **시선 떨림**이 과한지.
3. **접근** — 앞으로 다가갔다 물러나기 3회. near/far 전환이 **깜빡이지 않고** 자연스러운지.
4. **하이파이브 20회** — 손을 들어 유지→내리기 반복. **성공/실패/중복 발동/타인 손 오발동** 횟수 기록.
5. **2인 교차 10회** — 두 사람이 앞에서 엇갈림. **잘못된 대상 전환 횟수** 기록. (완전 겹침 후 동일인 보장은 한계)
6. **가림 & 복귀** — 대상이 잠깐 가려졌다 같은 자리로 복귀. 유예 내 **재연결**되는지.
7. **퇴장** — 대상이 나가면 **배웅 후 대기**로 돌아오는지.

## 내구성

- **30분 연속 실행**: 정지/프리즈 없는지, 메모리 증가 추세(작업관리자/브라우저 작업관리자), 카메라 분리→재연결 복구.

## 지연 측정 (권장 방법)

- **앱 내부 처리시간**: 운영자 패널의 인식 FPS와, 필요 시 코드에 타임스탬프 로깅 추가.
- **모션→표시 지연(엔드투엔드)**: 손을 화면 앞에서 ‘탁’ 치는 순간과 캐릭터 반응 순간을 **같은 프레임 영상**에서 세어 계산(예: 60fps 녹화에서 프레임 수 × 16.7ms). 카메라·디스플레이 지연이 포함됩니다.
